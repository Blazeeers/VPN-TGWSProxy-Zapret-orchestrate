# Changelog

Все заметные изменения проекта.
Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),

## [2.2.1] — 2026-10-22

Правки по ревью 2.2.0: аудит выключал VPN, ломал режим `proxy` и умел смотреть
только в одну сторону.

### Fixed
- **Юниты гасили VPN.** `omavpn-route-audit.service`, `omavpn-route-recheck.service`
  и `omavpn-guard.service` — `Type=oneshot` без `KillMode`, а `omavpn` запускает
  xray и sing-box через `start_new_session=True` внутри той же cgroup. По
  завершении юнита systemd убивал туннель: VPN ложился после каждого
  исправленного маршрута. Добавлен `KillMode=process` (проверено экспериментом:
  `setsid`-ребёнок oneshot-юнита с ним выживает, без него умирает).
- **Guard ломал «VPN выключен» и режим `proxy`.** `svc_youtube_ok` требовал
  ответа от `youtubei.googleapis.com`, который напрямую недоступен по
  определению. При выключенном VPN сторож каждые 10 минут запускал перебор
  zapret под root и включал VPN, а в `mode proxy` (без TUN) «ломался» навсегда.
  Теперь `youtubei` проверяется только при поднятом туннеле (`tun_up`).
- **Перепроверка снимала ручные оверрайды.** `--route-audit-recheck` трогал все
  оверрайды `proxy` старше суток. Теперь только свои — те, у которых `reason`
  начинается с «аудит». Ручной `omavpn route set` неприкосновенен (аудит его
  тоже не перебивает).
- **Аудит загонял в туннель домены из `ALWAYS_DIRECT_DOMAINS`.** `max.ru`,
  `deepseek.com`, `yandex*`, `tailscale*` требуют российского IP — теперь
  пропускаются с пометкой «только напрямую».
- **Лок аудита по mtime.** Прогон дольше 600 с позволял второму процессу забрать
  лок, а `finally` первого снимал уже чужой. Заменён на `flock`.
- **`route list` мог разойтись с конфигом.** Путь считался по точному имени, а
  sing-box сопоставляет суффиксы: поддомен `youtubei.googleapis.com`,
  записанный в `direct_domains.txt`, показывался как `direct`, хотя шёл в
  `proxy`. Теперь путь — проход по правилам в их порядке.
- **Проба картинок зависела от одного видео.** `dQw4w9WgXcQ/hqdefault.jpg` —
  удалят видео, и guard с аудитом будут считать CDN сломанным по кругу.
  Заменено на `i.ytimg.com/generate_204` (+ `favicon.ico` как `image/*` в guard).
- Кнопка «Проверить маршруты» в виджете неактивна при пустом `cliPath`, как и
  соседние.

### Added
- **Двусторонний аудит.** При провале на пути `proxy` домен переводится в
  `direct`, VPN перезапускается, домен проверяется заново; не помогло — откат
  и запись «не отвечает ни там, ни тут». Исключения: `ALWAYS_PROXY_DOMAINS`
  в direct не переводятся, `ALWAYS_DIRECT_DOMAINS` в proxy не уводятся. Не
  больше двух переключений на домен за прогон, пауза 2 с перед перепроверкой.
  Повод: 22.10.2026 в 02:19 `zapret-autotune` перевёл сеть в режим `vpn` и
  весь видеотрафик `googlevideo` ушёл в туннель, где не работает (видео
  `code=000`, страница 200) — аудит «только direct → proxy» этого не видел.
- **Один перезапуск вместо N.** Сначала все пробы, потом оверрайды пачкой с
  `--no-restart`, затем единственный `omavpn restart` и перепроверка. Плюс
  идемпотентность `route set`: путь не изменился — перезапуска нет.
- **Общий mutex на управление VPN**: неблокирующий `flock` на
  `~/.local/state/omavpn/ctrl.lock` вокруг `on`/`off`/`restart`/`route set`/
  `route unset`. Рестартеров теперь четверо (таймеры аудита, перепроверка,
  guard, кнопки виджета) — параллельные `on` сносили друг другу туннель.
  Занято — понятная ошибка «другой процесс управляет VPN».
- **Валидация домена в `route set`**: `*.googleapis.com`, `a..b`, `localhost`,
  IP, `x.com#comment`, кириллица — отказ с объяснением.
- `uninstall.sh` удаляет `~/.config/omavpn/route_overrides.json` и
  `~/.cache/omavpn/route-audit*.json` (даже без `--purge`): иначе после
  переустановки остаются оверрайды под другую сеть.
- `verdict: "fixed"` ставится только если после переключения проба реально
  прошла; в `summary` перечисляются домены, которые всё ещё не отвечают.

## [2.2.0] — 2026-10-22

### Added
- **Оверрайды маршрутов домена** (`omavpn route list|set|unset`,
  `~/.config/omavpn/route_overrides.json`). Запись вида
  `{"youtubei.googleapis.com": {"path": "proxy", "reason": "...", "ts": ...}}`
  сильнее всего остального: домен с `path: proxy` не попадёт в direct-правило,
  даже если `zapret-autotune` записал его в `direct_domains.txt`. Чтение и
  запись атомарные, битый JSON не роняет CLI — предупреждение в stderr, список
  считается пустым. `route set/unset` перезапускают VPN через существующую
  сборку конфига (`--no-restart` — без перезапуска).
- **Аудит маршрутов** (`bypass-status --route-audit`): проверяет список доменов
  (`ROUTE_PROBES` — YouTube, `youtubei`, `ytimg`, `googlevideo`, Discord,
  Telegram Bot API, DeepSeek), и если домен по текущему пути не отвечает, а
  через локальный SOCKS отвечает — ставит оверрайд `proxy`, перезапускает
  sing-box и перепроверяет. Если домен не отвечает обоими путями, он не
  переключается: это не про маршрут. Результат — `~/.cache/<cli>/route-audit.json`
  и журнал systemd. Только маршруты: `omavpn heal` и перебор нод не вызываются.
- **Перепроверка оверрайдов** (`bypass-status --route-audit-recheck`, раз в
  сутки): оверрайды `proxy` старше 24 часов снимаются, домен проверяется
  напрямую; работает — остаётся на direct, не работает — оверрайд возвращается.
  Так блокировка, которую сняли, перестаёт гонять трафик через VPN.
- Юниты `omavpn-route-audit.{service,timer}` (загрузка + 3 мин, затем каждые
  10 мин) и `omavpn-route-recheck.{service,timer}` (раз в сутки).
- В виджете — строка «маршруты: проверено N, исправлено M» / «маршруты в
  порядке», та же строка в подсказке иконки и кнопка **«Проверить маршруты»**.
- `docs/route-audit.md` — как работает аудит, какие домены проверяются, как
  откатить вручную.

### Fixed
- **YouTube «тормозил» при живом видео.** `youtubei.googleapis.com` (служебный
  API плеера) блокируется напрямую наглухо — все адреса дают таймаут 10 с, а
  zapret его не пробивает: домена нет в `/opt/zapret/ipset/zapret-hosts-user.txt`.
  При этом `www.youtube.com` отдаёт 200, а видео с `googlevideo.com` качается
  10–24 МБ/с, поэтому поломка выглядела как «интернет медленный». Домен и
  `youtube.googleapis.com` теперь в `ALWAYS_PROXY_DOMAINS` — всегда через VPN,
  отдельным правилом **перед** direct-правилом. Проверено: напрямую таймаут,
  через туннель ответ за 1–2 с (HTTP 405 на `GET /youtubei/v1/player` — норма).
- `omavpn-guard` проверяет `youtubei.googleapis.com` в `svc_youtube_ok`: успех —
  любой HTTP-ответ, `000` — поломка. Раньше сторож видел «YouTube работает»,
  пока плеер висел.

### Changed
- Приоритет маршрутов в `build_singbox()`: **override → `ALWAYS_PROXY_DOMAINS` →
  `direct_domains.txt` → `final=proxy`**. `youtube.googleapis.com` и
  `youtubei.googleapis.com` убраны из `DEFAULT_DIRECT_DOMAINS`.
- Без файла `route_overrides.json` поведение прежнее (кроме доменов из
  `ALWAYS_PROXY_DOMAINS`).

## [2.1.0] — 2026-10-21

### Added
- **`omavpn-guard` — надзиратель за обходами.** Фоновый сторож (`systemd --user`,
  проверка каждые 10 минут и через 2 минуты после загрузки) следит, чтобы
  YouTube, Discord и Telegram **работали**, а не просто «были настроены».
  - YouTube проверяется по-настоящему: страница с содержимым, превью картинкой
    (`image/*`, >2 КБ) и доступность медиа-CDN `googlevideo`;
  - Discord — шлюз `/api/v9/gateway` и сайт;
  - Telegram — живой юнит `tg-ws-proxy`, `api.telegram.org` и `web.telegram.org`.
- Лечение по цепочке, от мягкого к жёсткому: перезапуск `tg-ws-proxy` →
  `omavpn heal` → просьба к `zapret-autotune` перепроверить стратегии
  (`rescan.request`, ожидание по `.lastscan`) → перебор нод → и только в крайнем
  случае сломанный сервис уходит в VPN.
- Защита от «мигания»: кулдаун 15 минут на ручную смену пути, не больше трёх
  переключений в час, экспоненциальный бэкофф (до часа) после серии неудач,
  сброс счётчика при смене сети. Если `zapret-autotune` только что переписал
  `direct_domains.txt`, сторож в него не лезет.
- Юниты `omavpn-guard.service` / `omavpn-guard.timer` / `omavpn-autostart.service`
  (последний поднимает VPN при входе, если он был включён).
- Уведомления `notify-send` о том, что не чинится само (не чаще раза в час).
- `docs/guard.md` — как устроен надзиратель и когда он вмешивается.

### Fixed
- **YouTube рвался примерно на каждом пятом соединении**: TUN поднимался с
  `mtu 9000` при стеке `gvisor`. Теперь 1500 — на замерах 40/40 запросов вместо
  30/40.
- **Стек `mixed` полностью ломал VPN** (0 из 25 соединений) — зафиксирован
  `gvisor`.
- **Пароль при каждом `omavpn on/off`.** Причина: sing-box при `auto_route`
  перенастраивает DNS через D-Bus `org.freedesktop.resolve1`, и polkit каждый раз
  просил пароль. Добавлен шаблон правила
  `docs/polkit/49-omavpn-resolved.rules` (шесть действий, только свой
  пользователь, только локальная сессия).
- `omavpn off` теперь очищает `last_error`: раньше намеренное выключение
  выглядело как падение, и сторож поднимал VPN обратно.
- Ключ сети в `omavpn-guard` строится так же, как в `zapret-autotune`
  (интерфейс + SSID + MAC шлюза), поэтому решение автотюна читается и на
  проводном подключении.
- `omavpn status --json` в документации не работал — правильно
  `omavpn --json status`.

### Changed
- `omavpn-guard` **не выключает VPN**: он нужен для остальных заблокированных
  сайтов. Меняется только путь YouTube/Discord/Telegram — мимо VPN, пока обход
  справляется; в VPN они уходят лишь при отказе обхода.
- Каталог состояния сторожа — `0700` (там имена сетей и узлов).

## [2.0.0] — 2026-10-19

### Added
- **Монитор работоспособности VPN** — каждые 5 минут виджет запускает
  `bypass-status --health`: комплексный тест текущей конфигурации (реальный выход
  через туннель, служба и стратегия zapret, YouTube страница + скорость видео,
  Discord страница/шлюз/CDN, DeepSeek API, Telegram API через прокси VPN,
  tg-ws-proxy). Результат — вердикт, время и длительность проверки — кэшируется
  в `~/.cache/<cli>/health.json`.
- **Самовосстановление VPN** (`omavpn heal`): если туннель поднят, но трафик не
  идёт, монитор перезапускает его, а при неудаче перебирает серверы профиля и
  переключается на живой. Не чаще одного раза в 10 минут.
- **Подбор лучшего региона и сервера** (кнопка «Подобрать лучший»,
  `omavpn best [--apply]`, `bypass-status --optimize`): быстрый проход по всем
  нодам **всех** регионов подписки, затем подтверждающая серия проб на
  победителе; лучшая пара применяется и, если VPN включён, туннель
  переподключается на неё. Прогресс (регион/сервер, `nodes_done/nodes_total`,
  фаза) — в `probe.json`.
- **Строка Discord** в виджете: страница, шлюз `/api/v9/gateway` и CDN.
- **Строка DeepSeek API** и правило маршрутизации: `deepseek.com` / `deepseek.ai`
  добавлены в `ALWAYS_DIRECT_DOMAINS` — трафик ассистента к DeepSeek всегда идёт
  мимо VPN (через зарубежный выход API периодически рвался).
- Сгенерированные пиктограммы (`shell-plugin/bypass-status/icons/`) вместо
  шрифтовых глифов; значок панели и строки виджета показывают состояние цветом.
- Признак `caps_ok` в `omavpn status`: если у `sing-box` потерян `cap_net_admin`,
  виджет прямо говорит об этом и даёт одну команду восстановления.

### Changed
- **Плагин стал одним виджетом.** Точка входа плагина `io.github.blazeeers.omavpn`
  теперь — виджет **«Обходы»** (`shell-plugin/bypass-status/Panel.qml`); функции
  старого виджета подключения (включение/выключение VPN, страна, сервер) перенесены
  в него, тумблер **«Подключаться при входе»** добавлен в карточку VPN. Отдельного
  плагина `bypass-status` больше нет.
- `install.sh` кладёт виджет «Обходы» в каталог плагина `omavpn` вместе с
  пиктограммами и правит `entryPoints.barWidget` на `Panel.qml` (для локальной
  установки; при установке из git манифест используется как есть).
- Кнопка **«Проверить доступность»** заменена на **«Проверить всё»** —
  комплексный тест текущей конфигурации вместо четырёх HTTP-кодов.
- Кнопка **«Тест серверов»** стала **«Подобрать лучший»**: тестируются все
  регионы, а не только текущий, и победитель сразу применяется.
- Строка **«Серверы VPN»** убрана — регионы, серверы и результаты проб живут
  внутри карточки **VPN**.
- Перерисован виджет: карточка VPN с тумблером, полоса прогресса подбора,
  строки сервисов с иконками и подписями состояния, единый набор кнопок.

### Removed
- Кнопка **«Проверить YouTube»** — проверка YouTube входит в комплексный тест и в
  монитор (иконка и строка YouTube остались).
- Никаких запросов пароля при включении/выключении VPN: весь путь идёт от
  обычного пользователя, TUN поднимает `sing-box` с `cap_net_admin`; виджет не
  вызывает `pkexec`/`sudo` и сообщает, если capability пропала.

## [1.8.0] — 2026-10-17

### Added
- Виджет «Обходы»: кнопка **«Тест серверов»** — полный тест всех нод выбранного
  профиля. На каждую ноду поднимается отдельный временный Xray на свободном
  локальном SOCKS-порту (живой туннель не трогается) и через него идут реальные
  пробы до Discord; считаются медиана, p90, потери, TLS и оценка
  `med×0.4 + p90×0.6 + потери×1.5`. Неотвечающая нода помечается «нет ответа»
  после трёх подряд неудачных проб (~18 с вместо всех таймаутов). Прогресс и
  результаты — в `~/.cache/omavpn/probe.json`, виджет показывает их в раскрытой
  секции VPN (★ лучшая, ● текущая), клик по серверу переключает на него, кнопка
  **«Подключить лучшую»** — на лучшую по тесту.
- CLI `omavpn probe [--profile N] [--probes N] [--url URL] [--timeout S] [--node N]`
  — тот же тест из терминала; `omavpn status` отдаёт состояние теста в поле
  `probe`.
- CLI `bypass-status --vpn-test` — запускает тест серверов фоном (его и вызывает
  кнопка); `bypass-status --json` отдаёт прогресс/результаты в поле `vpn_test`.
  Повторный запуск при идущем тесте отклоняется («тест серверов уже идёт»), а
  оборванный тест (процесс умер) показывается как завершённый и не блокирует
  кнопку.

## [1.7.0] — 2026-10-08

### Added
- Виджет: строка **«Обновления»** стала кликабельной — по нажатию компоненты
  обновляются автоматически (`bypass-status --update-components`). tg-ws-proxy
  скачивается из последнего GitHub-релиза с проверкой sha256 по дайджесту из API
  релиза, бинарь подменяется (старый — в `.bak`), запущенный процесс
  перезапускается; zapret обновляется через `pkexec` + `pacman`, а если
  графического агента polkit нет — открывается терминал с `yay` (один раз
  ввести пароль). Кэш `updates.json` обновляется сразу, строка исчезает.
- CLI: `bypass-status --update-components`.

## [1.6.1] — 2026-10-08

### Fixed
- Проверка видео YouTube: следуем редиректам `googlevideo` (`curl -L`) — без
  этого загрузка с VPN падала с `302` и 0 байт, и проверка ошибочно показывала
  «видео не грузится».
- Автотюн: «YouTube работает напрямую» теперь проверяется по-настоящему —
  страница **и** скорость видео с `googlevideo` (`yt-dlp` + `curl`, порог
  ≥100 КиБ/с). Раньше проверялась только доступность страницы/CDN, из-за чего
  выбиралась стратегия, при которой видео всё равно не грузилось.
- Если видео не качается, перебор ищет общую стратегию для YouTube **и** Discord;
  если ни одна не помогает — оба сервиса уходят в VPN.
- Кнопка «Тест стратегий»: во время идущего перебора виджет показывает «перебор
  уже идёт» вместо тихого игнорирования; запрос пересоздаёт файл, чтобы
  systemd path-юнит сработал гарантированно.
- Установщик автотюна предупреждает, если не найден `yt-dlp`.

## [1.6.0] — 2026-10-04

### Added
- **Реальная проверка YouTube**: качается кусок видео с `googlevideo.com`
  (через `yt-dlp` + `curl`) и меряется скорость — ловит случай «страница
  открывается, видео не грузится» (троттлинг). Результат кэшируется
  (`~/.cache/<cli>/yt.json`) и показывается строкой в виджете; иконка трея —
  `YouTube` (жёлтая), если видео не грузится.
- Кнопки в виджете: **Проверить YouTube** (`bypass-status --yt`) и
  **Тест стратегий** (принудительный перебор zapret через
  `--rescan-request` + systemd `zapret-autotune-rescan.path`).
- Автотюн: прямая проверка YouTube теперь требует доступности и страницы, и CDN
  `googlevideo` — иначе YouTube не считается работающим напрямую.

  доступность».

  (Xray 26.3.27, sing-box 1.14.1, tg-ws-proxy 1.10.4).

  пользовательским симлинкам и не меняет владельца цели.

## [1.1.0] — 2026-09-26

### Added
- **Виджет «Обходы»** (`io.github.blazeeers.bypass-status`) — обзор состояния всех
  обходов прямо в панели Omarchy: VPN, zapret (DPI), tg-ws-proxy, Telegram-бот,
  плюс кнопка проверки доступности (Яндекс / Telegram API / YouTube). Цвет щита
  отражает здоровье системы.
- **`bypass-status`** — агрегатор статуса в JSON; сам определяет CLI (`omavpn`
  или `wowvpn`), root не требуется.
- `ALWAYS_DIRECT_DOMAINS` в CLI: российские сервисы (**Яндекс**, MAX) всегда идут
  напрямую, поверх `direct_domains.txt`; zapret-autotune их не перетирает.
- `install.sh` ставит оба виджета; в README — раздел «Виджет „Обходы“».

### Fixed
- **Яндекс не открывался при включённом VPN** — зарубежный выход режется
  провайдером/сервисом; Яндекс и MAX теперь исключены из туннеля всегда.

### Changed
- Проект и репозиторий переименованы в **VPN-TGWSProxy-Zapret-orchestrate**
  (поле `manifest.name`); id плагина прежний — `io.github.blazeeers.omavpn`.

## [1.0.0] — 2026-09-26

### Added
- **omavpn** — VPN-клиент (Xray-core + sing-box TUN) с виджетом панели Omarchy:
  профили/узлы, режимы TUN/SOCKS, автоподключение, проверка внешнего IP.
- Подписки в двух форматах: **Happ / Xray full JSON** и обычные **share-link**
  (`vless`, `vmess`, `trojan`, `ss`, `socks`; транспорты `ws`, `grpc`,
  `httpupgrade`, `xhttp`, `tcp`, `http`; безопасность `none`/`tls`/`reality`).
- **zapret-autotune** — автоматический подбор стратегии DPI-обхода под сеть,
  кэш по сетям, откат на VPN; systemd-сервис, таймер, хук NetworkManager,
  `AUTO_VPN`.
- Скрипты zapret: `zapret-setup.sh`, `zapret-hostlist.sh`, `zapret-strategy.sh`,
  `zapret-blockcheck.sh`.
- **tg-ws-proxy** — установщик локального MTProto-прокси для Telegram Desktop
  (ускорение без VPN).
- Документация: `docs/architecture.md`, `docs/zapret.md`, `docs/telegram.md`,
  `docs/troubleshooting.md`; атрибуция сторонних проектов в `THIRD_PARTY.md`.
- Манифест Omarchy Marketplace (`manifest.json` в корне) и лицензия MIT.
